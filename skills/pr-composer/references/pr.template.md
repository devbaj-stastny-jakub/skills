## Title
- Short human readable title for changeset
- Format: <JIRA_TICKET_ID>: <TITLE_SUMMARY>

## Summary
Provide 1 to 3 sentences describing changeset of pull request.
Description should be brief, simple and high level.
After this part, add 'key changes' section with few bullet points of those changes. Each point is one sentence.
Goal is to give initial context of changeset to reviewer.
User markdown and other formatting methods to make summary more readable.
Do not explain actual code changes, reviewer will read diff separately.
Do not explain, why something is done.

## Testing
Manual testing instructions for human. Should describe how changeset can be tested manually and include necessary instructions or materials so human can do it.
Do not list step-by-step testing instructions.

## Jira
Include link to Jira ticket. If no ticket is assignable to pull request, omit whole section.

## Notes
Include any additional notes that could be useful for reviewer. If there are no notes, omit whole section.

## UI Evidence
Include available screenshots, design links or videos. If none is available, omit whole section.
